# fx: effect engine (T28b, round-two support T28e, wired T28c, round three and its triggers T55)

Source art and rules: `design/fx/README.md` (the shipped set, the policy table) and, for the
round-two format, `design/fx/options/README.md` and `design/fx/options/render2.py` (the reference
compositor); SPEC rule 4. Effects are always on (no setting).

| Piece | What it is |
|---|---|
| `Fx` (generated by `:app:generateFx`) | One enum entry per `design/fx/<name>/` with a `meta.txt` (top level only). Wraps an `FxSpec` (`fx.spec`) and forwards its accessors: `Fx.byName("pow")`, `frameCount` (last frame is empty), `holdMs(i)`, `ink(i)` / `knockout(i)` / `cut(i)` layers, `tiles` + `tileLayer(t, i)`, `width`/`height`, `anchorRef/Dx/Dy`, `role`. |
| `FxSpec` | Everything about one effect. Each frame is split by symbol into disjoint `FxLayer`s. |
| `FxOptions` (test-only, `:app:generateFxOptions`) | The same generator run over `design/fx/options/` (the archive), compiled into the unit tests only. |
| `FxComponent` | The play-screen component (T28c): triggers, cancels, the KO/winner hand-shake, invalidation, drawing, the debug gallery. See "The component". |
| `FxPolicy` | Which effect: `trigger(net, ko, commander)` (size bands), `escalates`, `choose(seat, trigger, compact, narrowTier)` from per-trigger weighted pools (full / compact seat); a weighted random pick (injected `Random`) that never repeats the seat's previous one; `variant` (a `-narrow` twin on the narrow tier); `counterTrigger` / `toggleTrigger`. Table and weights in `design/fx/README.md`. |
| `FxPlayer` | Pure per-seat playback: `play`, `playAll` (one effect on many seats, one timer), `cancel`, `cancelAll`, `current(seat)`, `frame(seat)`, `group`, `holdScale`, `maxConcurrent` (2). |
| `FxRenderer` | Draws one frame: cut, tile layers, knock-out, ink (see "Draw order"); `draw(..., clip)` clips to the seat panel (or a compact seat's area above its drawer) when a footprint crosses it. On the device `#`, `o`, `x` and `fill` tile layers are drawn from rects (`FxLayer.rects`), not masks (see "Memory"). `prewarm`, `cutUnderlay`. |
| `FxLayout` | Pure placement maths: `place` (the frame footprint from the anchor box, plus the tile rect for `anchor tile`, and the rotation) and `textInkBox`. |
| `FxDebug` | Debug hooks set by `MainActivity` from intent extras (debuggable builds only). |

## Symbols and draw order

| Symbol | Layer | Drawn as |
|---|---|---|
| `x` | `cut(i)` | Invert under the mask (`DitherRenderer.drawMask(INVERT)`, blend DIFFERENCE): paper where the seat has ink, ink where it has paper. |
| `1`–`9` | `tileLayer(t, i)` | The tile named by `tile <d> <TILE> <mode>`, sampled at **global** screen phase: `ink` = ink where the tile has ink; `paper` = paper where the tile has ink; `fill` = the tile, opaque. |
| `o` | `knockout(i)` | `blit(invert = true)`: paper. |
| `#` | `ink(i)` | `blit`: ink. |

Every pixel holds one symbol, so the layers never overlap and the order cannot change the result. It
is fixed anyway (cut, tiles by ascending digit, knock-out, ink), and it equals `render2.py`'s
per-pixel `stamp` over the clean seat. `FxCompositeTest` checks this on every option, on both
seats, in both colour modes.

Rotation never touches the canvas. `#`/`o` use the blit's own rotation. `x` and tile layers are drawn
as the layer's turned view (`FxLayer.rotated`) on the untransformed canvas, so the mask turns and the
pattern phase stays global. Each turned view is one more scaled ALPHA_8 mask per rotation.

## The component (T28c)

`FxComponent`: `Layer.TILE`, `Kind.EFFECT`, no zones, registered in `PlayScreen` right after the
drawer (so it draws after the number, readout and drawer, before the layer's press inversion) and
before the KO tile. Timers: one per seat for `FxPlayer` (ids = seats) plus one for the gallery.

- **Trigger** (T55 timing, Sam: "waiting until the delta disappears is too slow"): a seat's effect
  starts **`FxComponent.QUIET_MS` = 300 ms after its last life change**, not at the readout's commit.
  One timer per seat in the component's own bank (`QUIET_TIMER + seat`), restarted by every change,
  cancelled by external changes, layout, detach and `Events.PAUSE`; no allocation. The readout stays
  up on its own schedule (3 s idle) and the effect plays alongside it. The component keeps its own
  net per seat (the readout zeroes its delta before its sink fires), mirrored from the same state
  diffs the readout adds: the seat's own life changes (`origin == seat`) and `Origin.ATTRIBUTED`
  life changes (commander damage on the target). The band is the running total when the timer fires.
  **Once per band per readout group**: taps that keep the total in a band play nothing more (a tap
  still cancels the running effect at touch-down); escalating into a bigger band of the same
  direction plays again; a smaller band after a bigger one never does (`FxPolicy.escalates`). A
  hold (±10 a second, first step at 500 ms) therefore plays once, at its first quiet gap, unless it
  escalates; a hold that reaches a KO stops there (the KO tile cancels the seat's touches) and the
  KO flourish plays 300 ms later. `Events.READOUT_COMMITTED` closes the group (and plays it if it
  committed before going quiet, e.g. on pause, or kept it while hidden). 300 ms: deliberate repeated
  taps come 150–250 ms apart, so a burst stays one group; on the panel a beat is ~250 ms, so the
  first keyframe lands about when the tap's own update settles. Tuned on the emulator (not e-ink):
  confirm on the Nomad.
- **Never under a finger** (T55 follow-up, the owner: "Effects should not trigger while a hold is in
  progress within that tile"): while any pointer is down on one of a seat's zones — life halves,
  commander quarters, drawer cells, the turn tab, pressed or not yet (`PlayInput.zoneOf` per pointer,
  `Stage.zoneSeat`) — that seat's quiet timer does not fire: it looks again every `HELD_POLL_MS`
  (100 ms, the same one timer) and, once the finger has lifted, runs a full 300 ms quiet from there.
  So a hold plays once, 300–400 ms after the release, sized by the whole group (a −30 hold: one crit,
  not one per step and none mid-hold); a hold that starts during an effect cancels it at touch-down
  and nothing replays until the release (and then only a bigger band). A group that commits while
  the finger is still down is kept and played after the release. Counter, toggle and commander
  effects the same. Other seats are unaffected; an all-seat effect (dusk/dawn) skips a held tile,
  as do the turn and first-player effects. Nothing is armed while paused.
- **Other triggers (T55)**, from the state diffs of a seat's **own** actions (`origin == seat`; so
  never undo, redo, a restore or a menu action, which are `Origin.EXTERNAL`): a counter gained
  (poison, energy, experience, rad, storm; tickets and generic play nothing), a toggle turned on
  (monarch, initiative, ring-bearer; the city's blessing plays nothing), day/night set to night or day
  (from either other state; unset plays nothing), and a revive (the KO tile's tap-tap: KO → alive
  with no life change). Each waits for the same 300 ms quiet as life, then plays if it is still a
  gain against the seat's player before the burst (a +1 −1 burst plays nothing), once per trigger
  per burst (until `BURST_MS` = 3 s pass without a change; a hold plays once). Life wins when both
  are pending. A counter the drawer doesn't list (`AppSettings.drawerCounters`) or a tracker the
  settings hide (`AppSettings.shows(Tracker)`, T53) plays nothing. **Commander damage taken**: the
  target's group (an `Origin.ATTRIBUTED` loss that changed its commander damage) plays the
  commander pool instead of a hit (a KO still plays the KO flourish); in commander mode it is kept
  and played when the number is back, like any commit there. **Turn passed** and **first player
  picked** dispatch as `EXTERNAL` (like an undo), so their components send `Events.TURN_PASSED`
  (turn tab, seat = screen: the new active seat plays) — one line. **First player (T65):** the
  sting is no longer an engine trigger: the d20 roll-off (`tools/FirstPlayer`) draws `start-flag`'s
  own frames on the winner's taken-over tile in its WINNER beat — up, wave, back, wave, glint
  (`FirstRoll.WAVE_FRAMES`, the second wave quicker) — under the roll's numerals and the FIRST
  pennant, once per roll-off; `Events.FIRST_PLAYER` is no longer sent (the trigger stays in the
  policy table for a future caller), so it never plays again when the tiles come back. A held correction of the turn (`SetActivePlayer`) plays nothing.
- **All seats at once (T55)**: night and day play `dusk` / `dawn` on every seat that can show an
  effect (alive, not covered, number visible) through `FxPlayer.playAll`: past the 2-seat cap,
  replacing plain effects there (a KO or winner flourish keeps its seat), stepped by **one** timer
  (`FxPlayer.groupTimer`), so each keyframe is one entry point, one invalidation union and one flush
  for the whole table. Cost: the same masks as one seat (one effect, the layout's rotations), and
  per keyframe a redraw of the union of the seats' footprints — on 4 seats most of the screen
  (as a gallery frame; each footprint is clipped to its panel) — once per keyframe, 4 keyframes; the
  panel only drives the changed pixels (dusk 567 / 1542 / 1169 / 440 flips per seat on the quad
  tile, so up to ~6 k a beat on 4 seats, ~9 k on 6). A touch on a seat stops it there only.
- **Compact seats** (drawer open): every effect is clipped to the area above the drawer (the union
  of `TileSlots.lifeFeedback` halves, i.e. the drawer's upper area), so it never draws over the
  drawer the player is using; life bands use the light number-anchored pools there.
- **Narrow tier**: a `<name>-narrow` twin, when there is one, replaces `<name>` (`crown-drop`,
  `torch`; `FxPolicy.variant`, by `PlayLayout.tier`).
- **External changes**: a commit that happens while another state change is being dispatched (the
  readout commits everything on undo, redo, new game, a menu action) is ignored, and the
  `Origin.EXTERNAL` change then stops every effect and quiet timer. So do a layout change, a
  player-count change and detach.
- **Cancel**: `Events.TOUCH_DOWN` on a seat stops its effect at once (one clean redraw of the stored
  footprint). A cover that hides the effect or the seat's number stops it there.
- **Commander mode** hides the number but not effects: a commit there is kept (summed) and played
  when the number is visible again (the mode closes). A full overlay hides effects: dropped.
- **KO hand-shake** with the KO tile (`ko/KoComponent`): when a seat's open life group takes it out
  (alive → KO with a negative net, number visible), the component sends `Events.KO_HOLD` from
  `onStateChanged` (the effects slot is before the KO slot, so no dead frame shows) and re-sends it
  on every further change in that group (re-arming the KO tile's 4 s safety net). Once quiet it plays
  `ko-shatter` (`fizzle` on a compact seat) with priority, and sends `Events.KO_RELEASE` when that
  ends, is cancelled (touch) or cannot play. A KO with no open life group (poison, a commander-mode
  KO, already dead) gets no flourish and no hold. Nobody listening = harmless.
- **Winner**: when one player is left, `winner` plays on the survivor once per game, alongside the
  last KO's flourish (or at once for a KO without one, or when the survivor's number is visible
  again). A restored or undone finished game does not celebrate again.
- **Cap**: `FxPlayer.maxConcurrent` = 2; a third seat just stays clean. KO and winner flourishes
  make room by stopping another effect (not a KO or winner one). Day/night is the one exception (all
  seats, above).
- **Paused**: between `Events.PAUSE` and `Events.RESUME` nothing starts and nothing is armed (a
  first-player pick landing on pause plays nothing).
- **Invalidation**: when an effect starts its footprint is stored per seat (`FxLayout.place`,
  clipped to the panel; the whole panel for tile-scale effects) and invalidated on every keyframe and
  on the clean step. Drawing culls by it.
- **Anchor box**: the number's whole `TileSlots.numberFootprint` (the sticker box with its shadow
  rows), not `textInkBox`'s cap band: that is the box `render2.py` anchored the designs to.
  `FxAnchorTest` checks every frame pixel for pixel, upright and turned, 1–3 digits.
- **Draw**: `FxRenderer.draw(spec, frame, footprint, panel, rotation, clip = panel)`, in the same
  pass after the number, so `x` cuts invert the drawn number. Dark mode needs nothing. On API < 29
  `cutUnderlay` is unset, so `x` layers are skipped there (the Nomad is API 30).
- **Prewarm**: only what `FxPolicy` can pick, narrow twins included (every effect while the gallery
  is requested), on the layout's own rotations, after the first frame (`Prewarm.LATER`).
- **Memory (T55)**: the renderer caches a scaled ALPHA_8 mask (S² bytes per dither px of the ink
  box) per image. Round three would have taken the effect masks from ~9 MB to ~24 MB at S = 4
  (emulator trace: 10.3 → 25.9 MB in all). So on the device `FxRenderer` draws the `#`, `o`, `x`
  (where the renderer inverts in place: API 29+, the Nomad) and `fill` tile layers from each layer's
  rects (`FxLayer.rects`: runs merged down the rows; 82 rects per frame on average, 883 at most,
  `winner`) with `rect`, `invertRect` and `fill`; only `ink` / `paper` tile layers (a sparse tile
  through a shape) keep a mask. Every mask cache in all: **8.2 MB** (was 10.3 before T55),
  prewarm after the first frame about the same (emulator, `docs/performance.md`). Pixel identity:
  `FxSpansTest` draws every frame of every effect at every rotation in both colour modes both ways.
- **No allocation** per keyframe or draw (`FxComponentTest` measures it).

## Timing (T65)

Owner: "a bit more push/pull on frame timings to give a slow-in/slow-out feel and improve
readability." Every shipped effect is timed as a curve, not a beat: the frame that carries the read
(the impact, the landed crown, the closed wreath) holds longest; the frames into and out of it are
shorter. `hold_ms` in each `meta.txt` is the **slow-display** curve (every hold ≥ 250 ms, SPEC rule
4); on a **fast display** (`eink/DisplaySpeed`) `FxPlayer.fastHold` derives the fast curve from it:
the read frame (the longest hold) keeps its hold, every other frame × `FAST_IN_OUT` (0.6), never
below `FAST_FLOOR_MS` (120). The speed is read when an effect starts. Chosen over a second authored
hold set per effect: one curve to tune per effect, and the push/pull grows automatically on a display
that can show it. `--ef fxHold X` still scales everything. `FxPlayerTest` pins the rule (one longest
read frame, nothing under 250 ms slow, the derivation). Totals stay within 50 ms of before. The
frames themselves are untouched (only `hold_ms` lines changed; the purity suite's effect keyframes are
the same pictures).

## Debug gallery (debuggable builds only)

Intent extras, read by `MainActivity` into `FxDebug`; never reachable from the UI:

| Extra | Effect |
|---|---|
| `--es fx <name>` | Sets every life to `fxLife` and plays that effect on all four seats at once, then 2 s clean, repeating until a touch. |
| `--es fx all` | The same, cycling through every shipped effect in `Fx` order (alphabetical), looping. |
| (T55) | The gallery plays every effect on every seat, `dusk`/`dawn` included; in play those two are the only all-seat effects. |
| `--ei fxLife N` | The gallery's life total (default 37, the total the designs were drawn over). |
| `--ef fxHold X` | Every hold × X (`FxPlayer.holdScale`), in the gallery and in normal play. |

The gallery drives the same component and draw path (the cap is lifted to four seats while it runs).
It sets the lives through the game, so they persist (one external change). The first effect starts
1.5 s after launch; the log line `fx gallery: <name> for <ms>` (with `--ez trace true`) marks each.

```
A=~/Library/Android/sdk/platform-tools/adb; P=au.com.josephmark.dithertracker
$A -s <serial> shell am start -S -n $P/.MainActivity --es fx quake               # one effect, looping
$A -s <serial> shell am start -S -n $P/.MainActivity --es fx all --ef fxHold 1.5 # every effect
```

## Adding an effect

Put the folder in `design/fx/<name>/` with an explicit `role` line, then add it to a pool in
`FxPolicy.DEFAULT_FULL` (and `DEFAULT_COMPACT` where the compact pool differs) with a weight, or leave
it for the gallery. A `<name>-narrow` folder is that effect's narrow-tier twin (no pool entry). `FxGeneratedTest` covers it automatically; update the
expected set in `FxPromotionTest`. Candidates stay in `design/fx/options/` until promoted.

## meta.txt as parsed

- `#` starts a comment, including trailing comments.
- Required keys: `size W H`, `frames N` (≥ 2), `anchor <ref> dx dy` (or `anchor dx dy` for
  centre), and `hold_ms h1 … hN`. The ref is `centre|tl|tr|bl|br|top|bottom|left|right` on the ink
  box, or `tile` on the seat tile. The last hold is 0 and every other hold is > 0.
- `tile <d> <TILE> <mode>`: one line per digit `1`–`9`. TILE is a name from `design/patterns/`, such
  as `D4`, `HLINES` or `CHECKER`, and the mode is `ink|paper|fill`. An unknown tile name, a bad
  mode, a repeated digit, or a frame digit with no `tile` line fails the build. A declared digit
  that no frame uses only warns.
- Optional keys: `role damage|heal|big-hit|ko|win|commander|poison|energy|experience|rad|storm|monarch|initiative|ring|night|day|turn|first-player|revive` (`FxRole`; T55 added the round-three ones), and `ink_px`/`knockout_px`/`cut_px`/`tile_px`/
  `flips` with N values each. The pixel counts are only checked loosely: a stale count prints a
  warning.
- `role` is required for shipped effects (the built-in fallback table is gone since T28c). In
  `design/fx/options/` (the archive, test-only) a missing role reads as `damage`.
- Frames must be exactly `frame-1.txt` … `frame-N.txt`, each H lines of W chars from `.#ox1-9`. The
  last frame must be empty.
- Any other key, a duplicate key, or a bad value fails the build with a `file:line` message.
- Generated data: each layer is a run-length code in string constants (`FxLayer.rle`), decoded once
  at class init. This keeps every class initialiser tiny and puts the bytes in the constant pool.
  At T28e, all 23 effects (shipped + options) generated 53 KB of source and 91 KB of class files, with the
  largest class at 12 KB.
