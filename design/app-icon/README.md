# App icon (T21)

The launcher icon, drawn in the app's own 1-bit language and generated by script. Pure black and
white, integer-scaled, no anti-aliasing in any file we ship.

## Concepts

All three are 54×54 "icon pixel" ASCII grids in `<concept>/icon.txt`. Each preview shows the full
108 dp canvas at 4× (ticks mark the 72 dp viewport), circle and squircle masks at 4× on white and
grey, and the same masks at 1× along the bottom.

| Concept | Preview | Idea |
|---|---|---|
| **sticker** (picked) | [`preview-sticker.png`](preview-sticker.png) | The hero "40" in the `num-l` sticker style, redrawn at 11×19 per digit with the checker drop shadow behind a 1-px paper keyline. Paper field. |
| diamond | [`preview-diamond.png`](preview-diamond.png) | The table centre: the stepped diamond in the `MENU` dither (D6) with the three menu bars on their paper backing, crossed by the dotted seat dividers. |
| heart | [`preview-heart.png`](preview-heart.png) | The `life` icon at 2× with a checker sticker shadow on a paper halo, over a Bayer ramp from D1 at the top to D8 at the bottom. |

**Why sticker.** The puffy "40" with its checker shadow is the app's signature: it is the first
thing on the play screen, and it says "Commander life tracker" without words. It is also the most
robust of the three:
- It is mostly solid ink on paper. Launchers resample the foreground by non-integer factors (see
  below). Solid shapes survive that with soft edges. Mid-dither fields like the diamond's D6 and the
  heart's ramp turn into grey mush or moiré, and the sparse end of the ramp looks like dirt on e-ink.
- It sits inside the 66 dp safe circle (furthest ink is 15.1 icon px from the centre; the limit is
  16.5), so circle, squircle and rounded-square masks never clip it. The first 13×23 draft reached
  the 72 dp edge, and the emulator's circle mask clipped the 4's foot and the 0's shadow.
- At 1× (36 px) it still reads as "40". The diamond reads as a texture and the heart as a blob.

The diamond is the runner-up. It is a good fit for a future themed or monochrome icon, but its
divider lines mostly fall outside the viewport, and its D6 fill is the first thing a launcher's
resampling destroys.

## Grid and densities

- 1 icon px = **2 dp**. The adaptive canvas (108 dp) is **54×54**. The 72 dp viewport that masks
  can show is the centred 36×36 (icon px 9..44). The 66 dp safe circle has a diameter of 33.
- Adaptive foreground `mipmap-*/ic_launcher_foreground.png`, every bucket an exact integer:

  | bucket | dpi | canvas px | device px per icon px |
  |---|---|---|---|
  | mdpi | 160 | 108 | 2 |
  | hdpi | 240 | 162 | 3 |
  | xhdpi | 320 | 216 | **4** |
  | xxhdpi | 480 | 324 | 6 |
  | xxxhdpi | 640 | 432 | 8 |

  The Nomad (300 dpi) resolves to the **xhdpi** bitmap: 216 px, 4 px per icon px, exact in the file.
- Background: flat `@android:color/white`. No vector, so there is no anti-aliasing.
- Legacy `ic_launcher.png` / `ic_launcher_round.png` (48 dp): the 36×36 viewport at the largest
  integer scale that fits, centred on paper. mdpi 48 → 1× + 6 px margin, hdpi 72 → 2×,
  xhdpi 96 → 2× + 12, xxhdpi 144 → 4×, xxxhdpi 192 → 5× + 6. The round version has a hard 1-bit
  circle, transparent outside. Note: with `minSdk 26`, every device takes
  `mipmap-anydpi-v26/ic_launcher.xml`, so the legacy PNGs are never used. They are kept because
  the task asked for them, and they cost about 3.5 KB.
- **What we cannot control.** `AdaptiveIconDrawable` draws the foreground at 1.5× the launcher's
  icon size, and the launcher filters it. The result is pixel-exact only when that size is a
  multiple of 54 px. On the emulator, the drawer icon is about 114 px across (about 3.17 px per
  icon px), so edges come out soft. See [`../captures/t21-launcher.png`](../captures/t21-launcher.png)
  (drawer crop, 4×): about 80% of the pixels in the disc are pure black or white, and the rest are
  edge greys from the launcher's resampling. The shipped bitmaps themselves are pure (checked in
  the APK: 1-bit grey / 2-bit palette, byte-identical in debug; release's crunched copy is still
  3 colours). The Nomad's own launcher icon size still needs checking on the device.

## Files

- `<concept>/icon.txt`: header (`#` comments, `size 54 54`, `fill <char> <TILE>`), a `---` line,
  then 54 rows. `#` is ink and `.` is paper. A `fill` character takes the named tile from
  `design/patterns/` at global phase (anchored to the canvas origin). `sticker` uses `:` = `CHECKER`
  for the shadow.
- `render.py`: stdlib-only renderer (PNG via zlib/struct). It writes the previews and the launcher
  resources for `PICK`.
- Generated: `app/src/main/res/mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher{,_round,_foreground}.png`,
  `app/src/main/res/mipmap-anydpi-v26/ic_launcher{,_round}.xml`.

## Regenerate

```sh
python3 design/app-icon/render.py                 # previews + launcher resources for PICK
python3 design/app-icon/render.py --previews-only # previews only
python3 design/app-icon/render.py --check         # exit 1 if committed resources don't match the ASCII
```

To change the icon, edit `<PICK>/icon.txt` and run the script. To switch concepts, change `PICK` in
`render.py`. Never edit the PNGs by hand.
